# 五维评分细则

## 1. 软件设计 (Software Design)

| 得分 | 标准 |
|------|------|
| 10 | 架构清晰，扩展性强，耦合合理，模式运用精准 |
| 7-9 | 设计合理，minor 扩展性或耦合问题 |
| 5-6 | 基本可用，但存在明显设计缺陷 |
| <5 | 架构混乱，难以扩展或维护 |

## 2. 业务逻辑 (Business Logic)

| 得分 | 标准 |
|------|------|
| 10 | 业务规则精准，流程完整，异常场景全覆盖 |
| 7-9 | 核心逻辑正确，少数边缘场景未覆盖 |
| 5-6 | 主流程正确，但存在逻辑漏洞或遗漏 |
| <5 | 业务规则理解有误或主流程存在缺陷 |

## 3. 代码逻辑 (Code Logic)

| 得分 | 标准 |
|------|------|
| 10 | 逻辑严谨，边界全覆盖，并发安全，资源无泄漏 |
| 7-9 | 逻辑正确，主要边界已处理，minor 并发风险 |
| 5-6 | 主逻辑正确，但边界或异常处理存在漏洞 |
| <5 | 存在明显逻辑错误或严重边界遗漏 |

## 4. 代码风格 (Code Style)

| 得分 | 标准 |
|------|------|
| 10 | 命名精准，结构清晰，注释恰当，完全符合规范 |
| 7-9 | 整体规范良好，minor 命名或格式问题 |
| 5-6 | 基本可读，但命名混乱或缺乏注释 |
| <5 | 难以阅读，命名无意义，结构混乱 |

## 5. 代码质量 (Code Quality)

| 得分 | 标准 |
|------|------|
| 10 | 性能优良，安全可靠，高度可测可维护 |
| 7-9 | 质量良好，minor 性能或安全风险 |
| 5-6 | 基本可用，但存在可维护性或安全隐患 |
| <5 | 性能差、有安全漏洞或难以维护 |
