# 治理规则（Review / Dedup / Merge）

## 目录

- Review：入库前过滤
- 事实性校验
- Dedup：候选集内去重
- Merge：与历史经验库合并

---

## Review：入库前过滤

**总原则：默认保留、定向过滤。** 宁可放过边缘经验，不可误杀好经验。

只拦截以下三类，外加无经验类别兜底：

1. **事实性错误或用户主观偏好**（garbage-patterns 第 1、5 类）；
2. **缺少上下文**（第 6 类）；
3. **粒度混用**（第 7 类）；
4. **无经验类别兜底**：三镜头（黑话/索引/逻辑）一个都不命中的候选。

对边缘候选（拿不准是不是经验）：**保留**，可在审计说明中标注不确定点。Review 的职责是挡垃圾，不是挑精品。

## 事实性校验

经验声称某 API / 方法 / 类 / 配置项存在时，必须在代码库中实际检索验证：

- **验证不通过** → 拦截，写入汇报中说明；
- **无法验证**（如涉及外部环境、历史决策、运行时行为）→ 条目中标记「存疑」并说明原因；
- **不得放行未验证的技术事实**。

## Dedup：候选集内去重

**总原则：宁严勿宽。** 拿不准就保留两条。

### 禁止合并的情况

- **When 不同**：两条候选的适用场景不同，即使结论相似也各自保留；
- **主结论类型不同**：一条是操作建议、一条是风险规避、一条是排查方法——类型不同不合并；
- **局部子机制 vs 完整系统**：一条讲子机制细节、一条讲整体系统，各自保留；
- **同一技术事实但用途不同**：事实相同、服务的目的不同，各自保留。

### 禁止桥接合并

A≈B 且 B≈C **推不出** A≈C。相似性不可传递，逐对判断，禁止通过中间条把多条链式合并成一条大杂烩。

**语义相似 ≠ 经验等价。** 判断等价的唯一依据是：召回后是否驱动相同的行为变更。

## Merge：与历史经验库合并

新候选与经验库已有条目之间，执行四动作之一：`create` / `update` / `skip` / `contradict`。

### 前置：唯一目标判定

先按 component / scope / 关键词召回相关历史经验。**若不存在唯一最合适的目标条目，默认回退 `create`**，禁止强行匹配到某个"差不多"的条目上。

### 四动作

- **create**：无对应历史条目，直接新增；
- **update**：存在唯一目标，且新信息是对同一经验的补充/修正。update 必须通过自检（见下），任一不过则**降级为 create**；
- **skip**：新候选与已有条目等价（驱动相同行为变更），不写入，汇报中说明；
- **contradict**：新候选与已有条目冲突。**不自动决断**——标记冲突、并列双方各自依据，交人工裁决，不擅自覆盖。

### update 自检清单

1. **When 是否过度泛化**：更新后的 When 不能超出证据支持的范围（证据只覆盖支付模块，就不能写成"所有服务"）；
2. **What 是否保留最具体可执行建议**：更新不得把具体命令/类名稀释成方向性描述；
3. **Why 是否保留核心机制**：原条目的机制解释必须保留或增强，不得丢失；
4. **是否引入无原始依据的新结论**：update 只能合并有证据的内容，禁止借机塞入推断。

任一项不通过 → 降级为 create（新候选独立成条，保留原条目）。
