# 阶段：编码实现

## 目标

按调用链自底向上完成代码改动，遵守红线与项目代码风格。

## 实现顺序

自底向上：数据 → 解析 → 枚举/协议 → 业务逻辑 → UI/接口 → 日志/埋点。

## 红线

- **RL-03 先看后写**：修改前先通读完整方法，搜索同类分支，禁止发明项目里独此一家的新模式。
- **RL-04 禁止硬编码**：样式走 UI 语义桥，协议字段走 DB/协议映射，配置走配置文件/常量表。
- **RL-07 不改未涉及文件**：只改定位阶段确认的改动点。

## 通用编码规范

- **单一职责**：一个函数/模块只做一件事，行长超过 40 行或嵌套超过 3 层时考虑拆分。
- **最小暴露**：对外接口只暴露必要行为，内部状态与实现细节隐藏。
- **依赖显式化**：依赖通过参数/构造函数传入，避免全局状态、单例滥用、隐式耦合。
- **边界清晰**：核心业务逻辑与基础设施（IO、网络、存储）分离。
- **错误处理**：使用项目统一的异常/错误码/Result 类型，禁止吞异常。
- **资源管理**：打开的文件、分配的资源、创建的对象都有对应释放路径。
- **并发安全**：跨线程/协程通信用项目约定机制，避免共享可变状态。
- **日志/埋点**：关键路径有日志输出或状态可观测。

语言相关细节（命名、头文件/包管理、框架 API、构建配置）以 `AIRunWorkDocs/agents/code_style.md` 为准。

## 小步验证

- 改完一个文件/模块后，优先编译/检查该模块或运行单测。
- 改完接口定义后，编译所有依赖该定义的模块。
- 禁止攒批一次性验证。

## 输出

- 修改文件列表
- 每个改动的理由（对应 subtask id）
- 小步验证结果
