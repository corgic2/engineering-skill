# 入口：Bug 修复

## 触发条件

用户报告一个具体 bug，或 `TECH_SPEC.md` §7 记录了待修复 BUG-N。

## 流程

1. **复现与收料**
   - 收集 bug 描述、复现步骤、日志、截图。
   - 若已有 BUG-N 记录，直接读取 `TECH_SPEC.md` §7。

2. **需求拆解**
   - 把 bug 拆成 1-3 个精确 subtask。
   - 在 `subtasks.json` 中新增条目，type 为 `BUGFIX`。
   - **HK-1**：确认修复范围。

3. **代码定位**
   - 用五步定位法找到根因位置。
   - 区分"症状点"与"根因点"，优先修根因。

4. **编码实现**
   - 最小化改动，优先添加边界判断/错误处理。
   - 同步补充日志或断言，便于后续排查。

5. **编译验证 + 运行验证**
   - 按 `stage_verify.md` 执行。
   - 若无法复现，记录到 `timeline.txt` 并报告用户。

6. **沉淀归档**
   - `TECH_SPEC.md` §7 新增 BUG-N 记录：现象、根因、改动文件、验证方式。
   - 更新 `subtasks.json`。
   - **HK-2**：沉淀确认。

7. **提交收尾**
   - commit message 标注 `Bugfix:` 与 BUG-N 编号。
   - **HK-3**：提交确认。
